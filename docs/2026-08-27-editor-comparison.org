#+TITLE: ClaudeEditor vs MutationEditor — the baseline half, measured
#+DATE: 2026-08-27
#+STATUS: HALF MEASURED — the MutationEditor baseline is real; the ClaudeEditor side is NOT RUN

* What this note is, and what it is not

S3's spec states that the *only* permitted claim about =ClaudeEditor= is
a comparison against =MutationEditor= at the same parent, budget and
objective. This note exists to hold that comparison.

*Half of it is missing.* The =MutationEditor= baseline below was run and
is real. The =ClaudeEditor= side *was not run* — this session had no
Anthropic credentials it was permitted to read, so no live-model
optimize run happened. Every =ClaudeEditor= test in the repo remains
stubbed, exactly as at S3's close-out.

So: *nothing in this note licenses any claim about =ClaudeEditor= at
all.* It is a baseline waiting for its other half, and it is filed now
because the baseline is what the comparison will be measured against,
and re-running it later under different conditions would be worse than
recording it under known ones.

* The run

Three runs, driven through the real CLI, one at a time, sequentially:

#+begin_src bash
SDL_VIDEODRIVER=dummy SDL_AUDIODRIVER=dummy PYTHONHASHSEED=0 \
./.venv/bin/python -m tuxghost.cli optimize \
  --trace tests/golden/scripted_town_1234.tuxghost \
  --editor mutation --seed $S \
  --objective reach-tile --target spyder_paper_town.tmx:19,14 \
  --rounds 32 --patience 32 --max-rejections 32 --max-cost 4000 \
  --out .../mut_s${S}.tuxghost --run-dir .../mut_s${S}
#+end_src

- Seeds $S ∈ {1, 2, 3}; 32 rounds, the tier at which the earlier sweep
  (=docs/2026-08-27-optimizer-tuning.org=) found =rounds= still
  unsaturated.
- =--patience= and =--max-rejections= are set equal to =--rounds= so
  neither can bind, the same construction the earlier sweep used.
- Parent: =scripted_town_1234.tuxghost=, 176 steps, digest
  =9eed41f8f05a2ac5f4ddab969eb3aba46c6768f541d22e01c6f16a45bd9270d6=,
  ends tile =[16, 14]= on a bare =WorldState=. Target =[19, 14]=, three
  tiles east — so the parent's own distance is =-3=.

*No wall-clock timings are reported.* Load average was 11-14 throughout,
from unrelated work on this host. The score data is unaffected: a seeded
=MutationEditor= run is deterministic, which the suite pins
(=test_a_seeded_run_is_reproducible_end_to_end=).

All three stopped on ="rounds exhausted"=; none on patience, none on
rejections. Zero rounds were rejected in 96 proposals, which continues
the earlier sweep's finding that =max_rejections= is unmeasured.

* The finding that matters: the mutator now ARRIVES

*Two of three seeds reached the target tile* — distance =-0.0=, seeds 1
and 3. The third improved distance from =-3= to =-2= while also cutting
steps from 176 to 125.

Against the retired parent this never happened once. Across that whole
nine-run sweep, all 60 accepted rounds were accepted on the =steps= term
and *no candidate ever scored better than the parent on distance*
(=docs/STATUS.org=). The difference is entirely the parent: appended
input reaches the player on =scripted_town_1234= and was swallowed by
=claude_town_1234='s trailing dialogue.

So the loop's ACCEPT path is now exercised through the distance term,
under a real search rather than a hand-written edit — the gap
=docs/STATUS.org= named and said would need a new fixture rather than a
code change.

** A caution about the two arrivals

Seeds 1 and 3 arrive at =186= and =185= steps, both *longer* than the
176-step parent. That is correct under a lexicographic objective —
distance outranks steps — but it means "best" here is not "shortest",
and a reader comparing only step counts would conclude the optimizer
made the trace worse. Seed 2, which did not arrive, has the shortest
winner of the three at 125 steps.

* What the ClaudeEditor side must do to be comparable

Same parent, same target, same four bounds, same 32-round tier. Three
runs, because =ClaudeEditor= has no seed and its variation comes from
sampling, so a single run cannot be distinguished from a lucky one.

With n=3 a side, the honest claim available is *whether the two ranges
separate* — not "one editor is better". The baseline's own range is wide
(best steps 125 to 186, arrival in 2 of 3), which should temper how much
a three-run Claude sample can be asked to show.

=ANTHROPIC_API_KEY= in the environment.
